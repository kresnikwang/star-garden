## 星夜花园 - shadowBlur 替换为发光精灵图

### 背景
Canvas 2D `shadowBlur` 每帧都会触发 GPU 模糊计算，在大量粒子场景下性能开销大。用预渲染的径向渐变小 canvas（sprite）替代，绘制时用 `drawImage` 直接贴图。

### 修改文件

**1. ParticleCanvas.tsx - 蓄力指示器圆环**
- 位置：`draw()` 中 `chargeProgress > 0` 分支
- 原来：`ctx.shadowBlur = 15; ctx.stroke(); ctx.shadowBlur = 0;`
- 现在：两层外发光描边（lineWidth 33 / 17，alpha 20% / 40%）+ 核心弧线
- 视觉上和原来 shadowBlur 接近，但免走 GPU blur pass

**2. ShareCard.tsx - 装饰粒子发光**
- 位置：`useEffect` 中 30 个装饰粒子的绘制
- 原来：`ctx.shadowColor = ...; ctx.shadowBlur = 10; ctx.fill(); ctx.shadowBlur = 0;`
- 现在：内联 `getGlowSprite` 缓存，预渲染径向渐变 sprite，用 `drawImage` 贴发光层再画核心圆

### 验证
- grep -rn "shadowBlur" src/ → 仅注释中提及，代码中无实际调用
- pnpm build 通过，无类型错误

## 星夜花园 - Canvas 性能优化（save/restore + Date.now()）

### 1. ctx.save()/restore() → 手动状态恢复（ParticleCanvas.tsx）

`drawParticle` 函数中每粒子调用 `ctx.save()/restore()`，开销是显式赋值的 3-4 倍。

**修改：**
- 去掉 `ctx.save()`
- 保留 `ctx.translate(p.x, p.y)` 和 `ctx.rotate(p.rotation)`（绘制逻辑需要）
- 6 个 `ctx.restore()` 全部替换为：
  ```js
  ctx.setTransform(1, 0, 0, 1, 0, 0);
  ctx.globalAlpha = 1;
  ```
- 涉及的粒子类型：petal、lighttrail、groundglow、echo、floater、默认路径（firework/charge/nebula/swipe/trail/sparkle/starfield/meteor）

### 2. Date.now() 提到帧循环顶部（ParticleCanvas.tsx）

ambient 粒子运动计算中每个粒子都调用 `Date.now()`（最多 150 次/帧）。

**修改：**
- 在 `animate()` 函数顶部计算一次：`const now = Date.now(); const timeSec = now * 0.001;`
- 替换循环内的所有 `Date.now()`：
  - 星星闪烁 `Date.now() * 0.001` → `timeSec`
  - 极光效果 `Date.now() * 0.001` → `timeSec`
  - ambient spring `Date.now() * 0.001` → `timeSec`
  - ambient summer `Date.now() * 0.002` → `now * 0.002`
  - ambient winter `Date.now() * 0.001` → `timeSec`
  - floater `Date.now() * 0.003` → `now * 0.003`
  - 蓄力指示器 `Date.now() - chargeStartRef.current` → `now - chargeStartRef.current`
  - 边缘脉冲 `Date.now() * 0.003` → `now * 0.003`
  - idleTime `Date.now() - lastInteractionRef.current` → `now - lastInteractionRef.current`
- 事件处理函数中的 Date.now() 保留（非每帧调用）
